## What the experiments must cover

Use a service, a command-line tool, and a documentation project. Give each
a distinct history and workflow. Include reversed decisions, completed
tasks, conflicting evidence, renamed files, and unapproved proposals.
Place some questions several sessions after the relevant change.

The main measure is the share of actions that use stale or unsupported
project knowledge. Also measure repeated completed work, attribution errors,
lost history, verification dates, tool calls, elapsed time, and maintenance
effort. Keep answer keys outside the guests. Score complete trajectories as
the independent units. Review ambiguous results without condition labels.

Use the [longitudinal test plan](test-plan-time.md) as the starting point.
Update its sample sizes and decision rules before the broader run. Preserve
the protocol, runner, fixtures, and result files in durable storage. Current
pilot artifacts under `/tmp/` need to be copied before temporary storage is
cleared. Keep credentials out of the saved experiment materials.

## What to resolve in the draft

- Define event dates and verification dates with examples from the failures.
- Clarify provenance, current state, replacement, and unresolved conflicts.
- State how deletion requests affect retained notes and derived summaries.
- Keep knowledge and execution authority distinct. Explain the host's role.
- Provide a simple default layout and a versioned local specification for
  offline use. Decide which parts are required and which are guidance.
- Check compatibility with v0.3 files and avoid unnecessary migration work.
- Keep fields only when their meaning and maintenance cost are justified.

## Candidate checks before publication

Test website setup, use without guest web access, and a fresh-agent handoff
with the candidate. Check local links, dates, retained status values, and
replacement references. Test one conflicting update, one deletion request,
and one note containing instruction-like text. Report the actual behavior
and the limits of these checks.

If we find a candidate defect, fix it and repeat the affected checks. If the
experiments remain inconclusive, v0.4 can still clarify the convention while
retaining experimental status. A claim of improved agent performance needs
the corresponding evidence.
