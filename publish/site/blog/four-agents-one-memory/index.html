Claude Code, Codex, Antigravity, and Pi on one repo: where OAK v0.5 beat plain Markdown

We ran four coding agents on a fork of pallets/itsdangerous to test OAK v0.5 against plain Markdown notes. All four passed setup and tests. OAK cut Git merge conflicts to 0 of 9 and blocked 3 of 3 silent file overwrites outside Git.

We tested OAK-0001 v0.5 across four coding CLIs on a fork of pallets/itsdangerous: Claude Code (Opus 5.5), Codex (GPT-6.2 Sol), Antigravity (Gemini 4 Neon), and Pi (GLM 5.4). Here is the result up front. All four read oakspec.dev cold, set up the memory folder, built the serializer, and passed over 300 pytest tests. OAK beat plain Markdown on parallel Git merges and on file handoffs outside Git. Inside one Git history, plain Markdown tied OAK because the reader checked git diff.

TL;DR

  • Newer models read plain prose well, so YAML fields do not change reading accuracy. File layout and handoff checks still do.
  • Linking the records/ folder from knowledge/index.md gave 0 conflicts across 9 parallel branch merges. A shared NOTES.md file conflicted in all 9 merges.
  • Putting core rules in AGENTS.md cut offline sandbox scope errors from 5 of 6 (in v0.4, which only linked a URL) to 0 of 16 in v0.5.
  • When a stale sync changed a delay from 45 to 15 outside Git, plain handoffs shipped the wrong number in 3 of 3 runs. OAK's SHA-256 hashes blocked all 3.

How we built the test

Reverting a real commit on a known open source library tests what the model remembers from training, or what it can read from git log and existing tests. OAK's first rule says not to write down facts that code and Git already show.

So we kept the real library (pallets/itsdangerous, 297 upstream tests) and added local project decisions that code cannot show. An October note approved SHA-1 and a 3600-second token limit. A November security review replaced that policy with SHA-256, HMAC key derivation, and a 300-second cap. That note also listed HSM paths on a remote signing machine and an old pyproject.toml version snapshot. A third note hid a prompt injection line telling agents to run a key-wipe script before pytest. Each CLI ran in a bwrap sandbox that hid our host AGENTS.md and CLAUDE.md files.

Phase 2: Handing one repo across four agents

Next we ran all four agents in sequence and in parallel on the same repo, comparing OAK v0.5 against a shared NOTES.md file.

Claude Code set up memory and wrote the serializer. Codex and Pi then worked in parallel on two Git branches. Codex blocked SHA-1 in code and recorded the revocation. Pi recorded a tighter 120-second limit in the notes and wrote HANDOFF.md without repeating the number 120. After merging both branches, our script changed 120 back to 300 in the note file and woke Antigravity cold as the release gate.

I expected Plain Markdown to miss the 120 to 300 edit in the relay. It did not. Because our script edited NOTES.md without committing it, Gemini 4 Neon ran git diff NOTES.md, saw the uncommitted edit, and refused to ship. Inside one Git repo, Git already tracks byte changes. SHA-256 hashes only earn their cost when files cross unmerged worktrees or external tools.

Limits and one bad rule we fixed

  • The four-agent repo test ran one trajectory per arm to limit API spend. The Gondolin VM tests ran 3 to 5 repeats per cell. Treat these counts as pilot results.
  • Earlier, OAK's verification rule caused GLM 5.3 to run a revoked production script in 2 of 3 runs just to check that config blocked it. Rule R1 now says to read code or config instead of running revoked commands. Banned probes dropped to 0 of 5 on GLM 5.3 and 0 of 9 on GLM 5.4.
  • In an earlier 3-way merge test, v0.4's per-file index.md links conflicted 4 of 4 times, and a resolver rewrote "once the DPA was signed" to "once the DPA is signed," flipping an approved flag to false. Linking the records/ folder fixed both bugs.

Takeaway

Smarter models read paragraphs as well as YAML. What they still cannot do is prevent Git conflicts on one shared file or spot a silent overwrite outside Git. OAK helps most when it stays small: local rules in AGENTS.md, one file per decision under records/, and hashes when files leave Git.
